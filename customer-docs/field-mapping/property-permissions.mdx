Permissions set what Ergo may write to your CRM. You set them for each record type and for each field.

## Who can use this

- The organization **Owner** and team **Admins**.
- A team Admin sees only the teams that the Admin manages.

## Before you start

- Permissions work together with the permissions of your CRM user.

## Steps

1. Open **Settings → CRM Settings**. Select the team at the top right.
2. On the tab **Permissions**, find the rows **Deal**, **Contact** and **Company**.
3. Turn off **Allow creation** if Ergo must not create that type of record.
4. Turn off **Allow updates** if Ergo must not change that type of record.
5. To give one person a different rule, click **Add user override** and select the person.
6. To stop writes to one field, open **Settings → CRM Properties**. Open the field. Set **Write behavior** to **Ergo will never write to this field**.
7. Process one meeting. Check that Ergo writes only what you allowed.

## What to expect

- Changes save automatically.
- The switches are on by default. They apply to the team that you selected.
- The tab has switches for a record type only. It has no switch for one field.
- A person with no override follows the team.
- A field also has the link **User overrides** below **Write behavior**.
- Ergo does not write a field in three cases: the permission for the record type is off, **Write behavior** is **Ergo will never write to this field**, or the field is read-only in the CRM.
- A read-only field still gives context for AI and for the board.

## Common issues

- Ergo does not write a field: check the three cases above.
- The CRM user can read a field but not update it: change the field security in your CRM.
- A **Member** sees only a personal CRM note template on **CRM Settings**.
